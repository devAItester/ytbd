# Шаблоны Markdown

В этом каталоге находятся Jinja2-шаблоны, из которых `ytbd` формирует Markdown-представления YouTube-каналов. Обычные шаблоны отображают сохранённый архив; `full.md` дополнительно включает сбор подробных метаданных видео, расширение метаданных плейлистов и ссылки на локальные материалы.

- [outline.md — обзор](outline.md): разделы канала со сворачиваемыми списками.
- [archive.md — архив](archive.md): подробные карточки записей с метаданными.
- [index.md — индекс](index.md): компактные списки ссылок.
- [full.md — полные метаданные](full.md): подробный JSON канала, видео и плейлистов, плюс локальные материалы.

## Как выбрать и запустить шаблон

1. Открой [workflow обновления архива](../.github/workflows/process-channels.yml) в GitHub Actions.
2. Нажми **Run workflow**.
3. Выбери шаблон в поле **Шаблон Markdown-представления** и запусти workflow.
4. После завершения открой `data/output/<канал>/`. Имя выходного файла соответствует имени шаблона без расширения `.md`: например, `outline.md` создаёт `data/output/<канал>/outline.md`.

Workflow сначала проверяет доступные разделы канала и обновляет архив, а затем рендерит выбранный шаблон. Для `full.md` по умолчанию подробно обрабатываются 5 уникальных видео, а из каждого плейлиста берутся первые 5 элементов; укажи `0` в поле ограничения, чтобы обработать все видео и элементы плейлистов. При включённом параметре локальных материалов сохраняются обложки, доступные субтитры и текстовые транскрипты — без скачивания видеофайлов.

Если YouTube отвечает `Sign in to confirm you're not a bot`, запусти сбор локально из корня репозитория. При необходимости добавь `--cookies-from-browser firefox` (или название своего браузера). Не коммить `cookies.txt` и не загружай его в репозиторий.

## Как изменить существующий шаблон

1. Открой, например, [outline.md](outline.md).
2. Нажми **Edit** в GitHub.
3. Измени Markdown, HTML или Jinja2-конструкции в файле.
4. Сохрани изменения через **Commit changes**.
5. Запусти workflow с этим шаблоном и проверь созданный файл в `data/output/<канал>/`.

Обычные заголовки, списки, ссылки и текст можно менять как в стандартном Markdown. Если меняешь Jinja2-выражения, используй только переменные и поля, описанные ниже.

## Как добавить новый шаблон

1. Создай файл в этом каталоге, например `compact.md`.
2. Напиши в нём Markdown и Jinja2-разметку. Начни с копии ближайшего по назначению файла: `outline.md`, `archive.md` или `index.md`.
3. Открой [workflow-файл](../.github/workflows/process-channels.yml) и добавь `compact.md` в список `options` для параметра `template`. Без этого пункта новый файл не появится в меню ручного запуска GitHub Actions.
4. Добавь имя нового шаблона в список `TEMPLATES` в `scripts/smoke_live.py`, чтобы live-проверка включала его.
5. Запусти workflow с новым шаблоном. Убедись, что результат создан и форматирование корректно.

Имя файла передаётся сборщику как параметр `--template`; путь должен быть относительно `templates/`. В имени параметра указывай имя файла с расширением, например `compact.md`.

## Доступные переменные

Сборщик передаёт в каждый шаблон следующие переменные. Они создаются в `scripts/process_channels.py` в вызове `template.render(...)`.

| Переменная | Тип и содержание |
| --- | --- |
| `title` | Строка: название канала. Если оно недоступно, используется запасное имя канала. |
| `channel_url` | Строка: нормализованный URL канала YouTube. |
| `channel_id` | Строка: ID канала, если он присутствует в метаданных; иначе пустая строка. |
| `checked_at` | Строка: время последней проверки в UTC. |
| `sections` | Список обнаруженных вкладок/разделов канала. Каждый элемент — объект с полями, описанными ниже. |
| `errors` | Список сообщений об ошибках сбора для текущего запуска; может быть пустым. |
| `template_name` | Строка: имя выбранного файла шаблона, например `outline.md`. |

### Поля элемента `sections`

Каждый `section` в цикле `{% for section in sections %}` содержит:

| Поле | Содержание |
| --- | --- |
| `section.key` | Машинный ключ раздела, например `videos`, `shorts`, `streams`, `podcasts`, `playlists`, `community`, `channels` или `about`. |
| `section.title` | Человекочитаемое название раздела. |
| `section.items` | Список записей из накопленного архива этого раздела. |
| `section.current_count` | Число записей в последнем успешно полученном списке источника. |
| `section.archive_count` | Число записей, сохранённых в архиве. |
| `section.collection_error` | Boolean: `true`, если сбор этого раздела в текущем запуске завершился ошибкой. |

### Поля элемента `section.items`

Каждый `item` в цикле `{% for item in section["items"] %}` — словарь метаданных записи. Состав исходных полей зависит от ответа YouTube/yt-dlp, поэтому не каждое поле обязательно присутствует.

| Поле | Содержание |
| --- | --- |
| `item.id` | Идентификатор записи в виде строки. |
| `item.title` | Название записи; если название отсутствует, используется ID. |
| `item.display_url` | URL для ссылки в представлении или пустая строка, если URL определить не удалось. |
| `item.upload_date` | Дата загрузки, если предоставлена источником. |
| `item.release_date` | Дата релиза, если предоставлена источником. |
| `item.duration` | Длительность в секундах, если предоставлена источником. |
| `item.description` | Описание, если предоставлено источником. |

Другие поля, возвращённые yt-dlp и сохранённые в записи, тоже могут быть доступны через `item.<имя_поля>`, но их наличие и формат не гарантированы. Чтобы выяснить точный состав данных конкретной записи, смотри соответствующий JSON в `data/channels/<канал>/archive/` и исходный ответ в `data/channels/<канал>/raw/`.

## Доступные конструкции Jinja2

Шаблоны обрабатывает библиотека [Jinja2](https://jinja.palletsprojects.com/en/stable/templates/). Используется окружение с `trim_blocks=True` и `lstrip_blocks=True`: управляющие строки шаблона не должны оставлять лишние отступы и пустые строки в результате.

### Вывести значение

```jinja2
# {{ title }}
<a href="{{ channel_url }}">{{ channel_url }}</a>
```

Внутри `{{ ... }}` пишется выражение, результат которого попадёт в документ. Для значений, вставляемых в HTML, используй фильтр `e` (escape), как в текущих шаблонах: `{{ title|e }}`.

### Условие

```jinja2
{% if channel_id %}
- **ID:** {{ channel_id|e }}
{% endif %}
```

Условие позволяет выводить блок только при наличии значения. Для логических полей, например `section.collection_error`, проверяй `{% if section.collection_error %}`.

### Цикл

```jinja2
{% for section in sections %}
## {{ section.title|e }}

{% for item in section["items"] %}
- {{ item.title|e }}
{% endfor %}
{% endfor %}
```

Циклы нужны для разделов и записей. Для доступа к полям словаря можно использовать точечную запись (`item.title`) или квадратные скобки (`section["items"]`).

### Фильтры и выражения

В текущем окружении доступны стандартные фильтры и выражения Jinja2, в том числе:

- `|e` — экранирует специальные символы для безопасной вставки в HTML.
- `|length` — длина строки, списка или другого поддерживаемого значения.
- `|default("текст")` — значение по умолчанию, если переменная не определена (для пустых значений при необходимости укажи второй аргумент `true`).
- `or` — выбрать запасное значение: `item.upload_date or item.release_date`.
- `not`, `and`, `==`, `!=` — логические проверки и сравнения.

Это не отдельный язык проекта: синтаксис и дополнительные встроенные возможности определяет версия Jinja2, установленная workflow.

## Markdown, HTML и пустые строки

Результат сохраняется как Markdown (`.md`) и отображается GitHub. Поэтому шаблон может сочетать:

- стандартный Markdown: заголовки, списки, выделение, ссылки и кодовые блоки;
- HTML, поддерживаемый GitHub Markdown, например `<details>` и `<summary>` для сворачиваемых блоков;
- Jinja2 для подстановки данных, условий и циклов.

Пример сворачиваемого раздела:

```jinja2
<details>
<summary>{{ section.title|e }} — {{ section.archive_count|e }} записей</summary>

{% for item in section["items"] %}
- {% if item.display_url %}<a href="{{ item.display_url|e }}">{{ item.title|e }}</a>{% else %}{{ item.title|e }}{% endif %}{{ "\n" }}{% endfor %}
</details>

```

**Следи за пробелами и переносами строк.** Jinja2 может убрать переводы строк рядом с управляющими тегами. В текущих шаблонах используются `{{ "\n" }}` там, где требуется гарантированный перенос строки. Закрывающий `</details>` должен оказаться на отдельной строке, а соседние пункты Markdown-списка — на разных строках. Не убирай такие переносы без проверки результата.

## Проверка результата

После изменения шаблона:

1. Запусти [workflow обновления архива](../.github/workflows/process-channels.yml) с нужным вариантом.
2. Открой сформированный Markdown в `data/output/<канал>/` и проверь заголовки, ссылки, списки, пустые строки и HTML-блоки.
3. При изменении структуры шаблона запусти [workflow проверки](../.github/workflows/validate-snapshot.yml).
4. Для live-проверки всех шаблонов используй `scripts/smoke_live.py` (он обращается к публичному YouTube-каналу и проверяет обнаруженные разделы и структуру результата).

## Откуда берутся данные и конструкции

- **Данные канала и записей** — публичные ответы YouTube, полученные через `yt-dlp` в `scripts/process_channels.py`.
- **`full.md`** выводит фактические поля yt-dlp без подмены схемой YouTube Data API. Для видео выполняется отдельный запрос без `--flat-playlist`; для плейлистов сохраняются метаданные и список элементов. `--detail-limit N` ограничивает подробный сбор и число элементов каждого плейлиста; `0` означает все. С `--download-media` сохраняются обложки, доступные субтитры и текстовые транскрипты, но не видеофайлы. Для локального запуска можно передать `--cookies-from-browser firefox` или `--cookies PATH`; файлы cookies не следует коммитить.
- **Список активных разделов** — ссылки навигации, обнаруженные на странице канала; набор разделов может отличаться у разных каналов.
- **Архив** — JSON-файлы в `data/channels/<канал>/archive/`; новые записи добавляются, а отсутствующие в текущем списке старые записи не удаляются автоматически.
- **Переменные шаблона** — явно передаются в `template.render(...)` в `scripts/process_channels.py`; поля `section` формируются функцией `make_sections()`, а поля `item` — из метаданных yt-dlp с нормализацией в `prepare_items()`.
- **Синтаксис шаблона** — Jinja2; Markdown и HTML интерпретируются уже при отображении результата, например на GitHub.

Главные исходники для сверки: [сборщик](../scripts/process_channels.py), [workflow запуска](../.github/workflows/process-channels.yml), [проверка шаблонов](../scripts/smoke_live.py) и [официальная документация Jinja2](https://jinja.palletsprojects.com/en/stable/templates/).
