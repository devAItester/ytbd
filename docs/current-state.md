# Текущее состояние ytbd

Дата фиксации: 2026-10-11.

## Кратко

Проект получает данные, сохраняет их и формирует Markdown. Основная незавершённая задача — не «добыть ещё JSON», а **сделать вывод понятным человеку**. Шаблон templates/full.md показывает слишком много необработанного JSON и пока служит скорее диагностическим представлением, чем удобной страницей.

## Что уже реализовано

### Получение данных

- Список каналов читается из config/channels.txt.
- Сборщик получает JSON метаданных канала через yt-dlp.
- Список вкладок канала определяется по публичному HTML. Распознаются videos, shorts, streams, podcasts, playlists, community, channels и about.
- Для вкладок запрашиваются плоские списки записей без скачивания видеофайлов.
- При выборе full.md дополнительно собираются подробные метаданные отдельных записей, с сохранением исходных полей.
- При включённом --download-media загружаются доступные изображения и дорожки субтитров на русском и английском языках; субтитры конвертируются в SRT, а из них создаются TXT-транскрипты. Само видео не скачивается.
- Для локального подробного сбора поддерживаются cookies-файл и --cookies-from-browser для yt-dlp. Cookies нельзя коммитить.

### Хранение и устойчивость

- raw/ содержит последние успешные исходные JSON-ответы.
- raw/history/ содержит разные успешные снимки, адресуемые по SHA-256.
- archive/ содержит накопленные записи: совпадающие ID обновляются, новые добавляются, пропавшие из текущего списка не удаляются автоматически.
- status.json сохраняет статус проверки и ошибки.
- Неудачный или некорректный ответ не должен заменять последний успешный снимок.
- Markdown формируется из локально сохранённых данных, отдельно от сбора.

## Что не используется

Проект **не вызывает YouTube Data API v3 напрямую** и не обращается к конечным точкам https://www.googleapis.com/youtube/v3/.... Это не означает, что API не способен вернуть аналогичные данные: это означает только, что текущая реализация использует yt-dlp и HTML-навигацию вместо официальных API-методов. Сопоставление приведено в таблице YouTube Data API: youtube-data-api-comparison.md.

Также проект не собирает комментарии и не скачивает видеофайлы. Данные об объектах и полях зависят от того, что фактически возвращает yt-dlp для конкретной записи.

## Следующий этап: оформление

Главная цель следующей задачи — перепроектировать templates/full.md как человекочитаемую Markdown-страницу, используя уже собранные данные.

Требования:

1. Показывать в основном представлении важные поля, а не печатать целый JSON на каждую запись.
2. Группировать поля по смыслу: идентификация и ссылки, публикация/трансляция, описание, технические сведения, локальные материалы.
3. Использовать заголовки, списки, компактные таблицы и карточки только там, где они повышают читаемость.
4. Скрывать редкие технические поля и полный исходный JSON внутри сворачиваемых блоков.
5. Не терять доступ к исходным метаданным.
6. Учитывать разные типы записей и отсутствие необязательных полей.
7. Ясно показывать предупреждения о неудачном сборе и потенциально устаревших данных.
8. Не менять сборщик и схему архива без отдельной подтверждённой необходимости.

## Проверки завершения

Задача считается законченной после того, как шаблон проверен на реальных сохранённых данных и тестовых примерах, автоматические тесты проходят, сформированный Markdown просмотрен на читаемость, а после слияния проверено опубликованное состояние. Одного успешного рендеринга недостаточно.

## Основные файлы

| Путь | Назначение |
|---|---|
| scripts/process_channels.py | Сбор, архивирование, подготовка контекста и рендеринг |
| templates/full.md | Полное представление; основная следующая задача — оформление |
| templates/archive.md | Архивные карточки с частью основных полей |
| templates/outline.md | Краткий обзор разделов |
| templates/index.md | Простой список ссылок |
| data/channels/ | Исходные данные, архив, история и статус |
| data/output/ | Сгенерированные Markdown-страницы |
