# ytbd — YouTube-архив и Markdown-представления

Добавь URL каналов, выбери шаблон представления и нажми **Run workflow**. Проект проверит актуальность открытых списков YouTube, обновит локальный архив и сформирует читабельные Markdown-страницы со сворачивающимися разделами. Для обычного запуска локальный терминал не нужен.

## 1. Добавить каналы

Открой [config/channels.txt](config/channels.txt), нажми **Edit**, добавь URL каждого канала на отдельной строке и сохрани через **Commit changes**.

Пример:

    https://www.youtube.com/@AsForJS
    https://www.youtube.com/@another-channel

Пустые строки и строки, начинающиеся с #, игнорируются. Повторяющиеся URL обрабатываются один раз. В файл добавляются только адреса — номера команд указывать не нужно.

## 2. Выбрать представление

Шаблоны находятся в [templates/](templates/). Выбери вариант при запуске:

- **outline.md — Обзор:** компактная страница со сворачивающимися разделами.
- **archive.md — Архив:** подробные карточки с дополнительными метаданными.
- **index.md — Индекс:** простой список ссылок.
- **full.md — Полные метаданные:** исходный JSON канала, подробные метаданные видео и плейлистов, а также ссылки на локальные обложки, субтитры и транскрипты.

Это Markdown-шаблоны с Jinja-разметкой. Сворачивающиеся блоки задаются тегами HTML `<details>` непосредственно в шаблоне, а GitHub отображает результат как отформатированный Markdown. Шаблоны можно редактировать или добавлять без изменения Python-скрипта.

## 3. Запустить обновление

Открой [workflow «Обновить архив YouTube и представления»](https://github.com/devAItester/ytbd/actions/workflows/process-channels.yml), нажми **Run workflow**, выбери шаблон и снова нажми **Run workflow**.

Workflow обрабатывает все каналы из списка. Никакие URL не нужно передавать в форме запуска.

## 4. Что собирается

Сохраняются метаданные канала и списки записей разделов. При выборе `full.md` сборщик дополнительно получает подробный JSON выбранных видео без `--flat-playlist`, а при включённой загрузке локальных материалов сохраняет обложки, доступные субтитры и текстовые транскрипты. По умолчанию в ручном workflow подробно обрабатываются 5 уникальных видео и первые 5 элементов каждого плейлиста; значение `0` означает все. Если YouTube блокирует запросы GitHub Actions антибот-проверкой, запусти сбор локально с `--cookies-from-browser firefox` (если Firefox авторизован в YouTube); не коммить файлы cookies. Шаблон выводит поля, реально полученные от yt-dlp, и не подменяет их схемой YouTube Data API:

- видео;
- трансляции;
- подкасты;
- плейлисты.

Сборщик не загружает видеофайлы, обложки, транскрипты и комментарии. Используется yt-dlp с плоским сбором метаданных; это не скачивание полного содержимого каждого видео.

## 5. Как устроено обновление

- При каждом запуске проверяется канал и каждый из четырёх списков.
- Новые записи добавляются в архив; повторяющиеся ID обновляются полученными метаданными.
- Если запись пропала из текущего списка, она не удаляется из архива автоматически.
- Неудачный запрос или некорректный ответ не заменяет последний успешно сохранённый JSON.
- Ошибка одного раздела или канала не должна останавливать обработку остальных; ошибки фиксируются в status.json и, если есть диагностика, в logs/.
- Повторно неизменившиеся файлы не перезаписываются. Сетевой запрос для проверки актуальности списка всё равно выполняется.
- При смене шаблона представления страница формируется из сохранённого архива; повторная загрузка видеофайлов не выполняется.

## 6. Где результаты

- **Метаданные канала:** data/channels/<канал>/channel.json.
- **Последние успешные исходные ответы:** data/channels/<канал>/raw/.
- **История разных исходных снимков:** data/channels/<канал>/raw/history/; одинаковые ответы не дублируются.
- **Накопленный архив записей:** data/channels/<канал>/archive/.
- **Статус последней проверки и ошибки:** data/channels/<канал>/status.json.
- **Страницы Markdown:** data/output/<канал>/<шаблон>.md.

Открой [каталог исходных данных](data/channels/) или [каталог представлений](data/output/). Результаты появятся после первого успешного запуска сбора.
