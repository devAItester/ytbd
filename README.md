# ytbd — YouTube-архив и HTML-представления

Добавь URL каналов, выбери HTML-шаблон и нажми **Run workflow**. Проект проверит актуальность открытых списков YouTube, обновит локальный архив и сформирует читабельные HTML-страницы. Для обычного запуска локальный терминал не нужен.

## 1. Добавить каналы

Открой [config/channels.txt](config/channels.txt), нажми **Edit**, добавь URL каждого канала на отдельной строке и сохрани через **Commit changes**.

Пример:

    https://www.youtube.com/@AsForJS
    https://www.youtube.com/@another-channel

Пустые строки и строки, начинающиеся с #, игнорируются. Повторяющиеся URL обрабатываются один раз. В файл добавляются только адреса — номера команд указывать не нужно.

## 2. Выбрать представление

HTML-шаблоны находятся в [templates/](templates/). Выбери шаблон при запуске:

- **outline.html — Обзор:** компактная страница со сворачивающимися разделами.
- **archive.html — Архив:** таблицы с дополнительными метаданными.
- **index.html — Индекс:** простой список ссылок.

Шаблоны — отдельные HTML-файлы с Jinja-разметкой. Их можно редактировать или добавлять без изменения Python-скрипта. Сворачивающиеся списки и структура страницы определяются шаблоном, а не зашиты в сборщик.

## 3. Запустить обновление

Открой [workflow «Обновить архив YouTube и HTML-представления»](https://github.com/devAItester/ytbd/actions/workflows/process-channels.yml), нажми **Run workflow**, выбери шаблон и снова нажми **Run workflow**.

Workflow обрабатывает все каналы из списка. Никакие URL не нужно передавать в форме запуска.

## 4. Что собирается

Сохраняются метаданные канала и плоские списки доступных записей разделов:

- видео;
- трансляции;
- подкасты;
- плейлисты.

Сборщик не загружает видеофайлы, обложки, транскрипты и комментарии. Используется yt-dlp с плоским сбором метаданных; это не скачивание полного содержимого каждого видео.

## 5. Как устроено обновление

- При каждом запуске проверяется канал и каждый из четырёх списков.
- Новые записи добавляются в архив; повторяющиеся ID обновляются полученными метаданными.
- Если запись пропала из текущего списка, она не удаляется из архива автоматически.
- Неудачный запрос или некорректный ответ не заменяет последний успешно сохранённый JSON.
- Ошибка одного раздела или канала не должна останавливать обработку остальных; ошибки фиксируются в status.json и, если есть диагностика, в logs/.
- Повторно неизменившиеся файлы не перезаписываются. Сетевой запрос для проверки актуальности списка всё равно выполняется.
- При смене HTML-шаблона страница формируется из сохранённого архива; повторная загрузка видеофайлов не выполняется.

## 6. Где результаты

- **Метаданные канала:** data/channels/<канал>/channel.json.
- **Последние успешные исходные ответы:** data/channels/<канал>/raw/.
- **Накопленный архив записей:** data/channels/<канал>/archive/.
- **Статус последней проверки и ошибки:** data/channels/<канал>/status.json.
- **HTML-страницы:** data/output/<канал>/<шаблон>.html.

Открой [каталог исходных данных](data/channels/) или [каталог HTML-вывода](data/output/). Результаты появятся после первого успешного запуска сбора.
