# Получение исходных данных YouTube через yt-dlp

## Цель

Сохранить исходные данные четырёх вкладок YouTube-канала до любых дальнейших преобразований:

- videos.json;
- streams.json;
- podcasts.json;
- playlists.json.

Канал: https://www.youtube.com/@AsForJS

Это первый этап процесса. Он не формирует tree-data.json, не раскрывает содержимое каждого плейлиста и не строит Markdown-дерево.

## Требования

- Linux или другая система, где доступен yt-dlp;
- рабочее сетевое соединение с YouTube;
- jq для необязательной проверки JSON из командной строки.

В зафиксированном примере использовался Arch Linux и yt-dlp 2026.08.19. Первая попытка получения данных завершилась по тайм-ауту; после включения VPN запросы прошли успешно. Это наблюдение относится к тому запуску, а не означает, что VPN всегда обязателен.

## 1. Проверить yt-dlp и создать каталог

    yt-dlp --version
    mkdir -p ~/youtube/AsForJS
    cd ~/youtube/AsForJS

## 2. Получить данные всех четырёх вкладок

Запустить весь блок целиком:

    for tab in videos streams podcasts playlists; do
      yt-dlp \
        --ignore-errors \
        --flat-playlist \
        --dump-single-json \
        "https://www.youtube.com/@AsForJS/$tab" \
        > "$tab.json" \
        2> "$tab.log"
    done

Для каждой вкладки команда сохраняет JSON в отдельный файл, а сообщения об ошибках и диагностике — в соответствующий лог. Перенаправление в файлы позволяет сохранить вывод для последующей проверки.

Параметры:

- --ignore-errors — продолжать обработку при отдельных ошибках;
- --flat-playlist — получать плоский список записей без отдельной полной обработки каждого видео;
- --dump-single-json — записать результат запроса в виде одного JSON-объекта;
- > "$tab.json" — сохранить стандартный вывод;
- 2> "$tab.log" — сохранить стандартный поток ошибок отдельно.

## 3. Проверить, что файлы созданы и JSON читается

    cd ~/youtube/AsForJS
    ls -lh videos.json streams.json podcasts.json playlists.json
    ls -lh videos.log streams.log podcasts.log playlists.log

    for tab in videos streams podcasts playlists; do
      printf '\n--- %s ---\n' "$tab"
      jq -e '.entries | length' "$tab.json"
    done

Команда jq должна вывести количество записей для каждого файла. Если файл отсутствует, JSON повреждён или структура отличается от ожидаемой, не переходить молча к следующему этапу: сначала изучить соответствующий .log и содержимое JSON.

Пустой лог сам по себе не доказывает полноту данных. И наоборот, наличие текста в логе требует изучения сообщения, но не всегда означает, что весь запрос завершился неудачно.

## 4. Сохранить полученные исходники в репозитории

Скопировать четыре JSON-файла и четыре лога в каталог примера в aishare, сохраняя имена:

Archive/YouTube Transcript Copy/summaries/yt-dlp/AsForJS/

После копирования проверить размеры и валидность JSON уже в целевом каталоге. Затем добавить файлы в Git, проверить список изменений, создать коммит и отправить его в GitHub. Не заменять эту проверку предположением, что копирование или команда Git обязательно завершились успешно.

## Результат этого этапа

Ожидаются восемь файлов:

- videos.json и videos.log;
- streams.json и streams.log;
- podcasts.json и podcasts.log;
- playlists.json и playlists.log.

В зафиксированном запуске получены 6 записей на вкладке видео, 253 — на вкладке трансляций, 21 — на вкладке подкастов и 24 — на вкладке плейлистов. Это снимок состояния канала на момент сбора; данные YouTube со временем меняются.

Следующий этап процесса начинается с уже сохранённых исходников: объединение метаданных плейлистов и подкастов, получение содержимого списков и создание tree-data.json. Эти преобразования описываются отдельно, чтобы происхождение исходных данных не смешивалось с дальнейшей обработкой.
